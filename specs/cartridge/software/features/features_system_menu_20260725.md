## 1. 概要と設計方針

本書はラテカピュータ（CAR-01）の**UIメニュー機構**の設計方針を定める。

### 1.1 経緯（用語ドリフトの解消）

旧版（Rev.0.1・2026-06）は「システムメニュー」という単一のオーバーレイメニューに、音量調整・（将来）アプリ切り替え・もどる等を混在させていた。その後、擬似マルチタスク機構の具体化に伴い次の点が変化した:

- **音量・輝度は「連続的な設定値」であって状態遷移ではない** → アプリ切替と同じメニューに混ぜるのは一貫性を欠く。
- **アプリ切替・スリープ・電源断・データ同期は「カートリッジ状態の切替＝状態遷移」** で同じ括り。
- **日本語入力はサブプログラムではなくなり、各アプリから呼び出すモジュール**になった。

これらを踏まえ、旧「システムメニュー」を**2つの別メニューへ分離**し、用語衝突（旧「システムメニュー」＝音量メニュー）を解消する。**素の「システムメニュー」という語は本書で廃止する。**

### 1.2 設計目標

- **UIコストをメイン基板（UIAPduino）から全面的に剥がす**。D基板（AVR64DD28）が全メニューのUI（描画＋入力捕捉）を単独所有し、メイン基板はUIコードを持たず**D基板からのコマンドを実行するだけ**にする。
- アプリ（3層）はメニュー機構の存在を原則意識せず、処理完了後に透過的に再開できること。
- UIはAVR64DD28とサブディスプレイ（CH1115 OLED・48×88ドット・4階調）で完結すること。

## 2. アーキテクチャ

### 2.1 役割分担（UIはD基板・実行はメイン基板）

```
ユーザー操作（ジョイスティック SKRHAAE010 ／ 各ボタン）
    ↓
D基板 AVR64DD28
    │ ・入力監視（常時）
    │ ・メニューUIの描画・ナビゲーション・選択を単独で担う
    │ ・現在のUIモードを保持し競合を裁く（単一アービタ）
    │ ・選択結果／要求をI2Cレジスタに置く（自発送信不可＝主がポーリング）
    │ I2C（共通バス・client/slave）
    ↓
UIAPduino（CH32V003・共通プログラム）
    │ ・I2CサービスループでD基板の要求を拾う（マスター）
    │ ・システム管理メニューの要求＝擬似MTオーケストレータ／電源協調／同期モードへ振り分け
    │ ・アプリ内メニューの操作コマンドをライブラリへ「パススルー」
    ↓
各デバイス／ハンドラ（YMF825音量・TFT輝度・アプリのセーブ/ロード等）
```

### 2.2 パススルー・ライブラリモデル（アプリ内メニュー）

アプリ内メニューの実体は**アプリへライブラリ（2層）として提供**する。**描画はライブラリが TFT（メイン表示）へ行う**（D基板OLEDではない＝アプリ文脈のUIだから）。入力はD基板が捕捉し、共通プログラムのI2Cポーリングを経てライブラリへ**パススルー**される。

```
入力: D基板(keyscan) → I2C → 共通プログラム(I2Cポーリング) → ライブラリへパススルー
描画: ライブラリ → TFT（メイン表示）
実行: ライブラリ → 実資源（音量=YMF825 / 輝度=TFT / セーブ・ロード・終了=アプリ/ライブラリのコールバック）
```

- 共通プログラム(1層)は**UIコードを持たない**（描画はライブラリ・入力捕捉はD基板）。「UIをメイン基板から剥がす」方針は、**システム級UI＝D基板OLED／アプリ文脈UI＝ライブラリのTFT描画**として維持される。
- D基板は**アプリ内メニューを描画しない**（D基板が描くのはシステム管理メニューとIME）。∴D基板へのメニュー内容pushは不要。

### 2.3 レイヤー位置づけ

```
┌─────────────────────────────────────┐
│  3層: アプリ（App Area）              │ ← アプリ内メニューはライブラリで利用
├─────────────────────────────────────┤
│  2層: 共通モジュール領域              │ ← アプリ内メニュー ライブラリ（候補）
├─────────────────────────────────────┤
│  1層: 共通プログラム                  │ ← I2Cサービスループ／管理メニュー要求の振り分け
└─────────────────────────────────────┘
UI描画・ナビ・入力捕捉は 1〜3層いずれにも属さず D基板 AVR64DD28 が単独で持つ
```

## 3. 2つのメニューの定義

| | **システム管理メニュー** | **アプリ内メニュー**（本書では「メニュー」） |
|---|---|---|
| トリガ | **MENU/CANCEL ボタン**（PF0） | **センタープッシュ長押し**（約1秒・ジョイスティック中央 PA7） |
| 所有 | D基板／システム側（アプリの上位） | 各アプリにライブラリ提供＝アプリ内 |
| 貫く概念 | カートリッジ状態の「切替＝状態遷移」 | アプリ内の環境・データ操作（コンテキスト切替なし・透過再開） |
| 優先度 | **最上位** | システム管理メニューにプリエンプトされる |
| 内容 | アプリ切替／システム提供サブプログラム呼出／スリープ・電源断／キーボード同期による導入・バックアップ | 音量・輝度（環境）＋セーブ・ロード |

> **命名の確定（2026-07-25）**: 切替側＝「システム管理メニュー」（画面表記は短縮「≡ システム管理」）。アプリ内側＝単に「メニュー」。旧語「システムメニュー」は用いない。

## 4. システム管理メニュー（切替系）

### 4.1 トリガと基本動作

- **MENU/CANCEL ボタン（PF0）** で開く。開いている間に再度押すと閉じてアプリ実行へ戻る。
- 最上位モード。開くとその瞬間から他メニュー（アプリ内メニュー・IME）は発火しない（§6）。

### 4.2 内容

| 項目 | 動作 | 実現 |
|---|---|---|
| アプリ切替 | 選択したアプリへ切替 or 新規起動 | 擬似MTオーケストレータ（REG_SWITCH経由） |
| システム提供サブプログラム呼出 | 常駐システムアプリのサブプログラムを選択 | `(app_id, resource_id)` の resource_id で選択 |
| スリープ | スリープ要求 | 3基板電源協調（D→主→A・§8） |
| 電源断 | 電源断要求 | 3基板電源協調（**独立の緊急経路は設けず本メニュー内の項目とする**） |
| 導入・バックアップ | アプリ／データをラテカピュータのキーボードと同期 | 外部通信モード（キーボードUART）＋カタログ投入（REG_APPLIST） |

### 4.3 アプリ切替＝2階層（確定・2026-07-26）

**第1層＝切替（横並び）**: **スロットに在席しているアプリのみ**＋末尾に **「新規起動」** を横並び表示。
- アプリ名を選択 → **切替**（既存スロットへ）。
- 「新規起動」を選択 → **第2層（ランチャ一覧）へ**。
- 項目が少ないので、名前が幅を超える場合の**横スクロール**はこの層に残る。

**第2層＝ランチャ（縦リスト・ページ単位切替）**: **カートリッジ導入済みの全ユーザーアプリ（最大50本）** を縦リストで表示。
- アプリを選択 → **新規起動**（オーケストレータがスロット確保・ロード）。
- 表示は**ページ単位の切替**（縦スクロールより再描画が速い）。
- 最大50本＝カタログ58エントリ（ユーザー50＋システム予約8・出典 `cartridge_master §カタログ`）のうちユーザーアプリ。システムアプリは常駐で"新規起動"対象外。

> 旧版の「実行中フラグの立つものだけ表示」および Rev.0.4 の「全格納アプリを状態マーク横並び」は**破棄**。在席アプリの切替（第1層）と、導入済み全アプリからの新規起動（第2層）を分離。新規起動か切替かの判定はメイン基板が権威的に行う（§8）。

**多階層ナビ**: システム管理メニュー内では **MENU/CANCEL ＝ 1段戻る**（第2層→第1層／第1層→閉じて通常）。管理メニューの外からは MENU/CANCEL ＝ 大域プリエンプトで開く（§6）。**第2層のナビ＝上下でページ内カーソル・左右で前/次ページ・センターで起動**（(C)確定・2026-07-26。第1層の「左右＝カーソル」と対称）。ページめくり後はカーソルを**新ページ先頭**へ・**ラップなし**（当面）。現在ページ表示（3/10等）は §11 レイアウトと併せる。

**名前画像の格納**: アプリ名4階調画像は**導入時（REG_APPLIST）にD基板Flashへ永続**する（[MT] 格納先＝Flash永続で確定）。∴リスト表示はメニューを開くたびの転送が不要＝**常に即時**。58×128B≈7.25KB＋フォント≈14.2KB＝約21.5KB／64KB Flashに余裕。

### 4.4 レイアウト

- **第1層（在席＋新規起動）＝横並び**、**第2層（ランチャ最大50）＝縦リスト・ページ単位切替**（§9.1）。
- スリープ・電源断・導入/バックアップの**画面上の配置は未指定＝PENDING**（§11）。**本書では新規レイアウトを発明しない。**

## 5. アプリ内メニュー（環境・セーブ系）

### 5.1 トリガと基本動作

- **センタープッシュ長押し（約1秒）** で開く。アプリが通常操作で使わない操作を選定（旧版踏襲）。
- アプリ実行を一時停止するが、**IAPコンテキストスイッチは行わない**（SRAM退避不要・軽量・透過再開）。
- **描画は TFT（メイン表示）にライブラリが行う**（D基板OLEDではない）。入力はD基板keyscan→I2Cパススルー（§2.2）。

### 5.2 内容と所有

| 項目 | 実資源 | 所有／実行 |
|---|---|---|
| 音量 | YMF825 マスターボリューム（Reg 0x19） | メイン基板（SPI） |
| 輝度 | **TFT**（メイン表示） | **メイン基板管理下**（D基板OLEDではない） |
| セーブ | 永続セーブデータ（FRAMセーブ領域へ書く） | アプリのコールバック |
| ロード | 永続セーブデータ（条件付き・§5.5） | アプリ／ライブラリ |
| **終了** | アプリをターミネート（32KBスロット解放）＋セーブデータ永続化（条件付き・§5.5） | ライブラリ(前処理)＋オーケストレータ(解放) |

いずれも操作の入力はD基板が捕捉し、§2.2のパススルーでライブラリへ届く。描画はライブラリがTFTへ、実行はメイン基板。

### 5.3 音量調整（旧版から継承）

YMF825のマスターボリュームレジスタ（0x19）をメイン基板がSPI経由で書き換える。追加部品・GPIO不要。

| レベル | レジスタ値（0x19） | 概要 |
|---|---|---|
| 0（無音） | 0x00 | ミュート |
| 1〜7 | TBD | 段階調整（7段階推奨・実機調整後確定） |
| 8（最大） | 0x1F（またはデフォルト） | 最大音量 |

スピーカーミュートは**物理スイッチ方式**（ケーブル上）。ソフト・GPIO制御は行わない（旧版踏襲）。

### 5.4 レイアウト

- 描画先は **TFT（メイン表示）**。項目＝音量／輝度／セーブ／ロード／**終了**／もどる。操作モデルは縦リスト＋`▶`カーソル（上下移動・左右で値変更・センターで確定）を踏襲するが、**TFT上の具体的な画素レイアウトは未指定＝PENDING**（TFTは旧OLEDスケッチ 48×88 と寸法が異なる・§9.2）。**新規レイアウトは発明しない。**
- メニューは末尾の **`もどる` 項目**で閉じる（センター長押し再操作方式は不採用・2026-07-25 確定）。

### 5.5 セーブデータ永続化（「終了」の前処理・コードサイズ条件付き）

**「終了」＝アプリをターミネート（32KBの擬似MTスロットを解放）する。** 併せて以下のセーブデータ永続化を行う。**この永続化そのものがコードサイズ増加量次第の採否対象**であり、見送る場合は「終了＝スロット解放＋セーブデータも消去」だけになる。

**★置き場所**: 永続化ロジック（終了前処理＋起動時復元）は**ライブラリ(2層)に置く**。擬似MTオーケストレータ側は「スロット解放」だけ＝**追加コード≈0**（1層・プールを食わない）。SPI Flash アクセスは `spi_flash_mgr`、2KBコピーは `chunk_copy`、FRAM入出力は `fram_read/write` を流用。

**SPI Flash システム予約領域のレイアウト**:
| 領域 | サイズ | 内容 |
|---|---|---|
| セーブデータプール | 16KB（2KB × 8スロット） | 各アプリのセーブデータ2KB・dedupeリング |
| app_id テーブル | 16B（2B × 8） | 各スロットに入っている app_id |
| 次スロットID | 1B | 空き割当用の書込ポインタ |

**終了時（バックアップ）**:
1. FRAM のセーブデータ領域(2KB)を SPI Flash のスロットへ書く。
2. **dedupe（Q1=A・app_id上書き）**: app_id テーブルに同 app_id があれば**そのスロットを上書き**（1アプリ1セーブ）。無ければ「次スロットID」の位置へ書き、テーブルに app_id を記録、ポインタを進める。8スロットが埋まった状態で新規 app_id が来たら最古を追い出す（リング）。
3. 32KB擬似MTスロットを解放。

**起動時（復元確認）**:
- アプリ起動（システム管理メニューで未起動アプリを新規起動する経路）で、アプリ初期化の頭にライブラリの復元チェックを呼ぶ。
- app_id テーブルに一致があれば **TFT に「復元しますか？ Y/N」を表示**（ライブラリ描画）。**Yes** で SPI Flash スロット → FRAM セーブデータ領域へロード。**No** で復元せず起動。

**明示ロード（アプリ内メニュー「ロード」・条件付き）**: アプリ起動後にメニューの「ロード」でセーブデータを選択してロード。**追加可否はコードサイズ増加量次第**（§11）。

**セーブ／ロード／終了 の分担**: 「セーブ」＝アプリが自分のセーブデータをFRAMセーブ領域(2KB)へ書く／「終了」＝そのFRAMセーブ領域をSPIリングへ吐いてスロット解放／「ロード（条件付き）」＝SPIリング→FRAMを実行中に行う。

**サイズ見積（ラフ・±40%・上記流用前提・すべてライブラリ2層）**:
| 部品 | 見積 |
|---|---|
| 終了時バックアップ | 60〜120B |
| 起動時復元＋Y/Nプロンプト(TFT)＋ロード | 80〜160B |
| **小計（自動永続化）** | **140〜280B** |
| 明示ロード（条件付き） | +80〜150B |
| オーケストレータ（terminate=スロット解放） | ≈0（数B） |

ハードな数字が要る場合はスクラッチ実測（実装→nm→破棄）で詰める。

## 6. モード排他仕様

**UIモードは常に1つ。D基板が単一アービタとして現モードを保持し競合を裁く。**
（システム管理メニュー・IME＝D基板OLED描画／アプリ内メニュー＝ライブラリのTFT描画、と画面は分かれるが、**入力モードの排他はD基板が一元的に裁く**。アプリ内メニューはセンター長押しをD基板が検知して入る＝D基板が状態を知る。）
優先順位＝**システム管理メニュー ＞ ｛アプリ内メニュー, IME｝ ＞ 通常**。
電源断は独立の緊急経路を作らず、システム管理メニュー内の項目とする。MENU/CANCELは大域プリエンプト。

| 現モード | MENU/CANCEL 押下 | センター長押し | アプリのIME起動コマンド |
|---|---|---|---|
| **通常** | システム管理メニューを開く | アプリ内メニューを開く | IMEを開く |
| **システム管理メニュー** | 閉じる→通常 | 無視 | 無視（拒否を返す） |
| **アプリ内メニュー** | 通常キャンセル（作業データ破棄）→管理メニューを開く | メニュー内ナビ | 起こらない（相互排他） |
| **IME** | 中断（作業データ破棄・**アプリへ入力キャンセル通知**）→管理メニューを開く | 起こらない | — |

補足規則:
- **アプリ内メニュー ⇄ IME は相互に起動しない**。当面**セーブファイルの自由命名を提供しない**ため、アプリ内メニューがIMEを必要とせず、この相互排他が成立する（自由命名を将来入れる場合のみ、この排他を見直す＝影響は隔離済み）。
- **★IMEキャンセル契約（必須）**: アプリはIME呼び出しで入力待ちにブロックされる。MENU/CANCELでIMEが中断された場合、**アプリへ「入力キャンセル（空文字列＋キャンセルフラグ）」を返す**。これによりアプリは「入力なし」として正常に継続でき、ハングを防ぐ。
- 「作業データ破棄」で捨てるのは**メニュー操作の途中の一時状態**であり、確定済みの永続データではない。またセーブ書き込みは協調型（非プリエンプティブ・I2Cはyield点でポーリング）ゆえ次のポーリング前に完走するため、書き込み途中で中断されることは構造的に起きない（アトミック性は自動保証）。
- システム管理メニューは**当面1画面に完結**させ、多階層化はニーズが出てから検討する（そのときMENU/CANCELの「全閉じ／1段戻る」を再設計する）。

## 7. 日本語入力の位置づけ

日本語入力は**メニュー項目ではない**。アプリが文字入力を要するとき、**アプリからD基板へ日本語入力UI起動コマンドを送信**して呼び出す**アプリ起点のモジュール**である（正本＝`CAR-01_japanese_input_20260717.md`）。

- D基板がフォント（8/12ドット・4階調）とIME UIを持つため、アプリ→D基板コマンドでIMEを起動しD基板がOLEDにUIを描く。
- 排他制御は§6のとおり。IME中はメニュー類を起動せず、MENU/CANCELのみがIMEを中断してシステム管理メニューへ遷移する（§6のキャンセル契約に従う）。

## 8. I2C連携

D基板は共通バスの client（slave）。プロトコルは**レジスタセレクタ方式**（SMBus流）。関連レジスタ（詳細は目論見書 `dboard_role_and_protocol_prospectus` §3.2 と D基板FW仕様を正本とする）:

| レジスタ | 方向 | 用途 |
|---|---|---|
| REG_INPUT | 主←D | 入力状態＋SYS_CMD（注意ビット） |
| REG_SWITCH | 主←D | アプリ切替の選択 `(app_id, resource_id)` |
| REG_SYSREQ | 主←D | 保留イベント（電源断等）の種別＋詳細 |
| REG_APPLIST | 主→D | 格納カタログ（名前4階調画像・app_id）1エントリ/tx |
| REG_RUNSET | 主→D | 権威ある実行中集合（フルビットマップ・起動/終了/切替完了で更新） |

- D基板は自発送信できないため、D→主 の要求（切替・電源断）は **注意ビット（SYS_CMD）＋保留イベント読み** で主基板がポーリングして拾う（事象チャネル）。level（入力状態）と event（切替・電源断）の切り分けはプロトコル目論見書 §3.2.1 を参照。
- **アプリ内メニューの入力パススルー経路**（D基板keyscan→I2C→共通プログラム→ライブラリ）とメニュー開閉/キャンセルのモード信号形式は**PENDING**（レジスタ形式未定・§11）。※アプリ内メニューはライブラリがTFTへ描画するため、D基板へのメニュー内容pushは不要。

## 9. OLED画面レイアウト

CH1115 OLED（48×88ドット・4階調）。**既存の与えられたレイアウトを維持し、未指定の新内容は本書で発明しない。**

### 9.1 システム管理メニュー（アプリ切替・2階層）

**2階層**（§4.3）:

第1層＝切替（横並び・在席アプリのみ＋末尾「新規起動」）:
```
 ▶ [在席アプリ名] [在席アプリ名] … [新規起動]
```
- カーソル＝`▶`。名前が幅（8×文字数 px）を超えれば**横スクロール**（省略しない）。

第2層＝ランチャ（縦リスト・ページ単位切替・導入済み全ユーザーアプリ最大50）:
```
 ▶ [アプリ名]
   [アプリ名]
   …（ページ単位で切替）
```
- **ページ単位切替**（縦スクロールより再描画が速い）。ナビ＝**上下＝ページ内カーソル／左右＝前/次ページ／センター＝起動／MENU/CANCEL＝第1層へ**（(C)確定・第1層の「左右＝カーソル」と対称）。めくり後カーソルは新ページ先頭・ラップなし。

- サブプログラム（システム提供）も第1層の在席系に含める（`(app_id, resource_id)`）。
- **スリープ・電源断・導入/バックアップの画面配置は PENDING**（発明しない）。

### 9.2 アプリ内メニュー（TFT・ライブラリ描画）

**描画先は TFT（メイン表示）**・ライブラリが描く（D基板OLEDではない）。下図は操作モデル（縦リスト＋`▶`カーソル）の参考で、**旧OLEDスケッチ由来。TFT上の具体的な画素レイアウトは未指定＝PENDING**（TFTは寸法が異なる・§11）:

```
（操作モデルの参考・寸法はTFTに合わせPENDING）
 ▶ 音量  [====----] 5/8
   輝度  [==------]         ← TFT輝度（メイン基板）
   セーブ
   ロード                   （条件付き・§5.5）
   終了                     （ターミネート＋永続化・§5.5）
   もどる                   ← このメニューを閉じる
```

- 上下でカーソル移動／左右で値変更（音量・輝度）／センタープッシュで確定。
- **末尾の `もどる` 項目で閉じる**（2026-07-25 確定）。項目数が画面に収まらない場合は縦スクロール。

### 9.3 共通

最下1ドットのバッテリ残量表示はD基板HW仕様 §6.2 のとおり（各モードで維持）。

## 10. D基板ファームウェアへの影響

D基板ファームウェア仕様（`boards_D_board_firmware_20260721.md`）の動作モードを更新する（**MCUは AVR64DD28**。旧版の ATtiny1604 記述は無効）。

| モード | 条件 | 動作 |
|---|---|---|
| 通常（LEVEL keyscan） | 通常時 | 入力状態をREG_INPUTで返答 |
| **システム管理メニューモード** | MENU/CANCELボタン検知時 | OLEDに切替UI表示・選択をREG_SWITCH/REG_SYSREQへ |
| **アプリ内メニューモード** | センター長押し検知時 | OLEDに環境/セーブUI表示・操作をパススルーコマンドで通知 |
| 日本語入力モード | アプリからのIME起動コマンド受信中 | ひらがな入力UI（§7） |
| スリープ | 電源協調でスリープ指示 | OLED表示オフ |

- モード状態の保持と排他（§6）はD基板側で管理する。
