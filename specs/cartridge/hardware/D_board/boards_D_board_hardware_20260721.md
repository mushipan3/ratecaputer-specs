## 2. 概要・目的

D基板はラテカピュータ（CAR-01規格）の日本語入力フロントエンドおよびシステムUI操作を担う専用基板である。AVR64DD28・CH1115 OLED・SKRHAAEジョイスティックの全機能をこの1枚に集約する。

ジョイスティック入力の監視・OLED描画（4階調ディザリング）・日本語入力UIをAVR64DD28が完結させ、UIAPduino（CH32V003）のCPU負荷を最小化する。日本語入力システムの詳細は `CAR-01_japanese_input_20260717.md` を、システムメニュー操作の詳細は `features_system_menu_20260615.md` を参照。

| 項目 | 仕様 |
|---|---|
| 基板サイズ | 19mm × 34mm（縦34mmはA基板・C基板とパネライズグリッドを統一） |
| 基板厚 | 0.8mm（JLCPCB 2層 FR-4） |
| 実装方式 | 片面実装 |
| パネライズグリッド | 19mm幅（B基板と同幅）・34mm縦（A基板・C基板と統一） |

**ケース内配置方針：**
SKRHAAE010のDIP変換キット（2.54mmピッチ）の実装面積が支配的。ジョイスティック操作面をケース窓から露出させる位置に配置する。OLEDもケース表面の窓から露出させる。

## 4. 回路設計

### 4.1 搭載部品

| 部品 | 型番 | 仕様 | 備考 |
|---|---|---|---|
| MCU | AVR64DD28 | AVR DD-Series・28ピン・64KB Flash・8KB SRAM・最大24MHz・MVIO・**DMA非搭載** | I2Cスレーブ＋OLED描画（4階調ディザリング）＋ジョイスティック制御＋ローカルフォント格納 |
| OLED | CH1115 | 0.5インチ・48×88ドット・I2C（0x3C） | 共通I2Cバス接続・描画はAVR64DD28が単独担当（4階調は時間的ディザリング） |
| ジョイスティック | Alps Alpine SKRHAAE010（秋月 AE-SKRHAAE010-BO） | 4方向＋センタープッシュ・デジタル5ポジション | プルアップ抵抗実装済みDIP変換キット |

### 4.2 ピンアサイン（AVR64DD28・**物理ピン割当は PENDING #7**）

> **【PENDING #7】AVR64DD28（28ピン）の物理ピン割当はユーザーが別途決定する。** 選定経緯（§8参照）どおり、
> ジョイスティック・各ボタン端子を基板の片側へ寄せる物理配置を優先するため、物理ピン番号はレイアウト設計と
> 併せて確定する。本表は**論理信号セット**のみを示し、物理ピン（Pxn）はAVR64DD28データシートに照合のうえ確定する。

| 論理信号 | 方向 | 接続先 | 備考 |
|---|---|---|---|
| LOCAL_UPDI_D | INOUT | UIAPduino PD0（エッジパッド経由） | セルフアップデート用。アップデート中はe-ink描画停止/TFT版は拡張デバイスCS解放が必要 |
| SDA | INOUT | 共通I2Cバス SDA | UIAPduino・ATtiny202と同一バス。CH1115もこのバスに接続 |
| SCL | IN | 共通I2Cバス SCL | 同上 |
| JOY_RIGHT / LEFT / UP / DOWN / CENTER | IN | SKRHAAE010 各端子 | プルアップ済み・LOW=押下（5入力） |
| VCC_3.3V | — | A基板 Pad3（VCC_3V3_OUT） | |
| GND | — | 共通GND | |
| （予備多数） | — | — | 28ピン化で予備ピンに余裕。将来拡張用 |

**LOCAL_UPDI_Dの兼用制約：**
UIAPduino PD0はe-ink版ではBUSY_EINK、TFT版ではGPIO4_CSとしても使用する。AVR64DD28アップデート中はe-ink描画コマンドを送らないこと。TFT版は拡張デバイスのCSをネゲートすること。UPDIは1対1接続専用。ATtiny202（A基板）はUIAPduino PD6（LOCAL_UPDI_A）で別途接続。同時アップデート不可。

### 4.3 ジョイスティック仕様

**Alps Alpine SKRHAAE010（秋月電子 AE-SKRHAAE010-BO）**

| 項目 | 仕様 |
|---|---|
| 方式 | デジタル5ポジションスイッチ（アナログ軸なし） |
| 方向数 | 4方向（上・下・左・右）＋センタープッシュ |
| 接点形式 | スイッチ接点（プルアップ時・押下でLOW） |
| 定格 | 50mA / 12V DC |
| 外形 | 7.35×7.5×1.8mm（SMD） |
| 動作寿命 | 200,000サイクル |
| キット付属 | 10kΩプルアップ抵抗実装済み・2.54mmピッチDIP変換基板 |

**ジョイスティック入力ビットフィールド（I2C返答フォーマット・1バイト）：**

```c
#define JOY_UP      0x01  // PA5 LOW
#define JOY_DOWN    0x02  // PA6 LOW
#define JOY_LEFT    0x04  // PA4 LOW
#define JOY_RIGHT   0x08  // PA3 LOW
#define JOY_CENTER  0x10  // PA7 LOW
// bit5〜bit6: 予備（将来拡張）
// bit7: 1=システムコマンド（SYS_CMD）・0=RAWデータ
```

### 4.4 4階調時間的ディザリング表示

CH1115は物理的に2値（点灯/消灯）OLEDだが、**4階調（2ビット）を時間的ディザリングで再現する**。4階調に対応する
複数プレーンをタイマ割込で高速に切り替えてI2C送出し、残像効果で中間調を見せる。フォント・描画データは
**主基板TFTと同一の2ビット4階調規格**を共有する（同一アセットを主基板・D基板・入力フォントで統一）。

- **AVR64DD28はDMA非搭載**（AVR-Dx系はDMAコントローラを持たない）。プレーン送出のI2C転送は**タイマ割込＋ポーリング**で
  組む。8KB SRAM・最大24MHzのリソース増により、ディザリングのプレーン保持と定周期送出のオーバーヘッドを吸収できる
  （ATtiny1604の1KB SRAM・16KB Flashでは余地が無かった＝MCUグレードアップの主目的の一つ）。

### 4.5 ローカルフォント（2ビット4階調・2サイズ）

D基板は入力UI用フォントを**ローカルFlashに保持**し、UIAPduino/SPI Flashへの往復なしに描画を完結させる。

| サイズ | 1文字あたり | 用途 |
|---|---|---|
| 小（8ドット） | 16B（2ビット4階調） | 候補文字列・選択文字群 |
| 大（12ドット） | 36B（2ビット4階調） | 最上位入力・変換中文字列 |

- 文字集合＝**入力サブセット約280字**（全角 英数/かな/カナ/記号）。2サイズ合計 = **約14.2KB（64KB Flashの約22%）**。
  FEP制御・辞書サブセットを含めても余裕がある。
- **混在レイアウト**（最上位=12ドット・候補=8ドット）を同一画面で同時に扱うため2サイズをローカル保持し、D基板単独で
  ゼロ遅延に描画する。主基板SPI Flashのフォントと**同一2ビット規格**（統一インデックス空間の部分集合）。

### 6.2 OLED仕様（CH1115）

CH1115（0.5インチ・48×88ドット）はD基板上に実装し、D基板内でAVR64DD28のSDA/SCLと接続する。共通I2Cバスを通じてUIAPduinoからも認識可能（アドレス0x3C）だが、描画はAVR64DD28が単独で担当する（4階調は時間的ディザリング・§4.4）。

**画面レイアウト（横長・高さ48×幅88ドット）：**

```
┌─────────────────────────────────────────┐  ← 上端
│  確定文字列（9ドット）                     │
├─────────────────────────────────────────┤  ← ライン（1ドット）
│  変換対象ひらがな文（9ドット）              │  区切り対象文字列は反転表示
├─────────────────────────────────────────┤  ← ライン（1ドット）
│  候補文字列群（24ドット）                  │  3行 × 8ドット
├─────────────────────────────────────────┤  ← ライン（1ドット）
│  バッテリー残量（3ドット）                 │
└─────────────────────────────────────────┘  ← 下端
```

**バッテリー残量表示仕様：**

| 項目 | 仕様 |
|---|---|
| 1ブロックのサイズ | 幅8ドット × 高さ3ドット |
| 1ブロックの表す残量 | 10% |
| 満充電（100%）の幅 | 80ドット（8ドット × 10ブロック） |
| 表示位置 | 下端3ドット・左寄せ |
| 端数ブロックの演出 | ゆっくり点滅 |

## 8. 設計根拠メモ

### AVR64DD28採用理由（ATtiny1604からのグレードアップ）

旧仕様ではATtiny1604（tinyAVR 0-Series・14ピン・16KB Flash・1KB SRAM）を採用していたが、以下の理由でAVR64DD28
（AVR DD-Series・28ピン・64KB Flash・8KB SRAM・MVIO）へグレードアップした。

1. **物理配置（レイアウト）上の制約が決定的**: ジョイスティックと各ボタンの端子を基板の**片側へ寄せて配線する**
   必要があり、14ピンのATtiny1604では**反対側にも多くのピンを基板のへりまで引き回さねばならず、配置的に無理があった**。
   **あえてパッケージサイズが大きくなってもピン数の多いパッケージを選定**し、端子を片側に集約できるレイアウト自由度を得た。
   （＝ピン数の余裕はレイアウト最適化のためであり、全ピンを機能で使い切る意図ではない。§4.2予備ピン参照。）
2. **リソース増で4階調ディザリング＋ローカルフォント格納の余地が生まれた**: 1KB SRAM/16KB Flashではディザリングの
   プレーン保持・2サイズ4階調フォント（約14.2KB）の格納に余地が無かった。8KB SRAM・64KB Flashでこれらを収容できる（§4.4/§4.5）。
3. **DMA非搭載は許容**: AVR-Dx系はDMAコントローラを持たないが、ディザリングのプレーン送出はタイマ割込＋ポーリングで
   成立する（大きいSRAM・クロックで吸収）。「D基板がDMA本命」という当初の見立ては誤りで、DMAは不要と確定した。

なおATtiny202（A基板・2KB Flash）との使い分けは従来どおり: A基板は電源管理等の小機能、D基板はOLED描画・日本語入力UI・
システムメニューUI・フォント格納を担うため大容量MCUが必要。

### SKRHAAE010採用理由

Alps Alpine製デジタル5ポジションスイッチ。アナログ軸なしのためADC不要・デジタルGPIOのみで制御できる。秋月電子でプルアップ抵抗実装済みDIP変換キット（AE-SKRHAAE010-BO）として入手でき、実装・配線が容易。動作寿命200,000サイクルはラテカピュータの想定使用年数に対して十分。

### LOCAL_UPDI_D接続先（PD0）

旧仕様（Rev.3.1）ではUIAPduino PD6に接続していたが、PD0/PD6のUPDI割り当て入れ替えによりPD0に変更した。PD0はe-ink版ではBUSY_EINK・TFT版ではGPIO4_CSと兼用であり、AVR64DD28アップデート中はそれぞれ描画停止・CS解放が必要。

### OLEDをAVR64DD28が単独管理する理由

UIAPduino（CH32V003）のCPU負荷を最小化するため。日本語入力候補表示・システムメニューUIともにAVR64DD28側で完結させることで、UIAPduinoはFM音源・SPI Flash・ゲームロジックに専念できる。
