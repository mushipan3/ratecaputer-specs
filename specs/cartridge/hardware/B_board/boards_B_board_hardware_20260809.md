## 2. 概要・目的

### 2.1 拡張の3本柱

1. **FMステレオ化**：YMF825-EZを2個搭載し、左右チャンネルを独立制御（独立した音色・音量・パン）
2. **PSG/ADPCM追加**：CH32V303がステレオPSG生成＋ADPCM再生を担当
3. **ミキシング/DSP**：FM・PSG・ADPCMをCH32V303主導でデジタル/アナログ混合し、将来的なDSP拡張の土台とする

### 2.2 アーキテクチャ方針

CH32V303を「専用オーディオコプロセッサ」として新設する（案A採用）。

```
UIAPduino（CH32V003・メインMCU）
    │ UART（高レベルコマンド＋ADPCM一括転送、DMA活用）
    ↓
CH32V303（オーディオコプロセッサ・本基板新規搭載）
    ├─ SPI（専用バス・UIAPduino本線とは分離）
    │     ├─ CS_YMF_L → YMF825-EZ (L)
    │     ├─ CS_YMF_R → YMF825-EZ (R)
    │     └─ CS_FLASH → W25Q128JV（ADPCM音声データ・16MB SPIフラッシュ）
    │     （SCK・MOSIは共有、CSのみ分離 → 独立した左右発音制御を実現）
    ├─ DAC ×2ch → PSG+ADPCMをデジタル合成後、L/Rそれぞれアナログ出力
    └─ 外付け8MHz水晶（HSE+PLL）
```

旧spec §7.1記載の「SCK/CS/RST共有・MOSIのみ分岐」方式では、両YMF825に同一コマンドが同時着弾し独立ステレオ制御ができない（二重化モノラルに留まる）。CS分離（GPIO+1本）により真のステレオを実現する。

UIAPduinoは音源制御から解放され、高レベルコマンド送信およびゲームロード時のADPCMデータ一括転送をUART経由で行う。SPI生信号がCH32V303に閉じ込められることで、外部（基板間）エッジパッドも簡素化される（§6.1参照）。

## 3. 物理仕様

### 3.1 基板寸法

| 項目 | 仕様 |
|---|---|
| 基板サイズ | 27.8mm × 33.3mm（旧仕様 19mm×27.8mmから拡大） |
| 基板厚 | 0.8mm（JLCPCB 2層 FR-4、現行踏襲） |
| パネライズグリッド | 長辺33.3mmをA・C・D基板と統一（3枚取りパネル効率化） |

**変更理由：** ①YMF825×2・CH32V303・出力段2系統化に伴う実装面積確保、②FRISKケース内蔵制約、③パネリング効率（3枚取り）。

### 3.2 スタック配置

旧spec §3.2の積層図は19×27.8mm前提のため、33.3mm版として再設計が必要（PENDING #5）。

### 3.3 GNDプレーン設計方針（音質対策・ゾーン限定方式）

旧spec §3.3は「裏面（Bottom）は信号配線なし・全面GND銅箔」という全面適用の音質対策方針だったが、新B基板では以下の通り**ゾーン限定方式に緩和**する。

| 対策 | 内容 |
|---|---|
| 裏面配線禁止エリア | SPOUT1/2（YMF825アナログ出力）・MCP6001差動入力まわりのアナログGND独立ゾーン直下のみ |
| 裏面配線許可エリア | 上記以外（CH32V303⇔YMF825/W25Q128JVのSPIバス、UART、電源配線等） |

これにより実効的な配線可能面積をほぼ倍近くまで回復できる見込み（§3.4の面積懸念を緩和）。なお、A基板の「片面実装・裏面全面GNDベタ」は製造上の理由（片面実装基板）であり本方針とは別の話である。

**KiCad実配置時のゾーン境界線設計指針：**

基板を「完全デジタルゾーン（CH32V303・W25Q128JV・水晶・SPI/UARTバス）」と「クリーンアナログゾーン（YMF825アナログ出力・MCP6001・PAM8302A・ヘッドフォンジャック）」に空間的に分離する。CH32V303の144MHzクロックおよびSPIバスの高周波ノイズが、MCP6001周辺のYMF825 SPOUT微小信号（差動アナログ出力）に飛び込まないよう、基板上で明確なゾーンセパレーションを確保することがS/N比確保の最大の防壁となる。GNDプレーンの結合点は「DAC出力およびMCP6001基準電圧（VREF）付近の1点」に集中させるスターGND構成とする（このサイズ・密度の基板での最も有効な手法）。12.288MHz水晶（X1・X1'）はYMF825の各XI/XOピン直近に配置し発振ループ面積を最小化する。

### 3.4 基板面積・部品フットプリント概算

基板面積27.8mm×33.3mm＝925.7mm²に対し、主要部品のフットプリント概算をプロト版（手はんだ前提）と量産版（JLCPCB PCBA前提）に分けて記載する。

|---|---|---|---|---|
| YMF825-EZ | SSOP-24 | 154（×2） | SSOP-24 | 154 |
| CH32V303CBT6 | LQFP48 | 81 | LQFP48 | 81 |
| W25Q128JV | SOIC-8 | 48 | WSON-8-EP(5x6) | 30 |
| MCP6001 | SOT-23-5 | 18（×2） | SOT-23-5 | 18 |
| PAM8302A | MSOP-8 | 14 | MSOP-8 | 14 |
| ヘッドフォンジャック（J1） | PJ-393-7A | 87 | PJ-393-7A | 87 |
| 水晶×3 | SMD3225-4P | 24（×3） | SMD3225-4P | 24 |

## 4. 回路設計

### 4.1 電源構成

| 電源ライン | 供給元 | 電圧 | 主な用途 |
|---|---|---|---|
| VCC_3.3V | A基板 Buck DCDC（RT8008-33GB相当） | 3.3V | YMF825×2 VDD/IOVDD/VREF、MCP6001×2 VDD、CH32V303 VDD/VDDA |
| AMP_5.0V | A基板 MT3608 | 5.0V | PAM8302A VDD、YMF825×2 SPVDD |

**電流容量の検討結果：**
- VCC_3.3V系（RT8008-33GB、最大600mA）：CH32V303追加・YMF825/MCP6001の倍化を加味しても余裕あり。CH32V303はVCC_3.3V系のみ使用しAMP_5.0V系には影響しない。
- AMP_5.0V系（MT3608、A基板設計値は出力電流目安300mA）：本基板はLINEOUT方式（内蔵BTLアンプ不使用）のためYMF825のSPVDDはほぼ待機電流のみ（数mA程度）。スピーカー駆動時のPAM8302A消費電流（200〜300mA程度）が主たる負荷となり、300mA枠は安全圏に収まる見込みが極めて高い（PENDING #1参照・実測で最終確認推奨）。

**CH32V303 VDDAの分離方針：** DAC/ADC精度確保のため、VDDAはデジタルVDDからフェライトビーズ＋独立デカップリングで分離する。

### 4.2 YMF825-EZ ×2 ステレオ接続

L/R独立制御のためCSのみ分離し、SCK/MOSI/MISOはバス共有とする。RST_YMFは2チップ共有（GPIO節約）。CH32V303自身のリセットもシステムNRST（UIAPduino基準）と共有する。

| 信号 | 接続 | 備考 |
|---|---|---|
| SPI_SCK | CH32V303 ⇔ YMF825(L)・YMF825(R) 共有 | |
| SPI_MOSI | CH32V303 ⇔ YMF825(L)・YMF825(R) 共有 | |
| SPI_MISO | CH32V303 ⇔ YMF825(L)・YMF825(R) 共有（オプション） | 通信確立確認用 |
| CS_YMF_L | CH32V303専用GPIO → YMF825(L) SS_N | 独立CS |
| CS_YMF_R | CH32V303専用GPIO → YMF825(R) SS_N | 独立CS |
| RST_YMF | CH32V303専用GPIO → YMF825(L)/(R) RST_N 共有（RST_SYS経由でCH32V303自身とも連動） | 同時リセット |
| IRQ_N(L/R) | オプション | ピン数次第で省略可 |

クロックはYMF825ごとに独立した12.288MHz水晶（X1・X1'）を実装する。XI/XOはピアス発振回路の能動素子であり、2チップを同一水晶へ並列接続すると発振回路同士が干渉し不安定化・周波数ズレのリスクがあるため（詳細は§8）。旧spec §4.3のYMF825ピン接続仕様（接続禁止ピン等）はL/R両チップにそのまま適用する。

### 4.3 ADPCM音声データストレージ

W25Q128JV（16Mバイト・SOIC-8・NORフラッシュ）を、C基板（UIAPduinoのプログラムライブラリ用FRAM/Flash）とは独立してCH32V303近傍に搭載する。CH32V303の音声用SPIバス（§4.2）にCS_FLASHとして相乗りさせる。

| 信号 | 接続 | 備考 |
|---|---|---|
| SPI_SCK | CH32V303 ⇔ W25Q128JV（YMF825と共有） | |
| SPI_MOSI | CH32V303 ⇔ W25Q128JV（YMF825と共有） | |
| SPI_MISO | CH32V303 ⇔ W25Q128JV（YMF825と共有） | 読み出し必須のため本チップではMISO必須 |
| CS_FLASH | CH32V303専用GPIO → W25Q128JV CS | 独立CS |

**採用理由（独立ストレージ化）：** C基板のSPIバスはUIAPduinoのIAPコンテキストスイッチで随時使用される。ADPCM再生中にこのバスへ相乗りすると音切れ・ノイズの原因になりうるため、CH32V303専用のローカルストレージとした。素子選定の詳細経緯（FRAM案の検討と棄却）は§8参照。

### 4.4 CH32V303クロック設計

外付け8MHz水晶を採用する（HSE→PLLで144MHz等に逓倍）。内蔵HSI使用は不採用とした（理由は§8参照）。

### 4.5 PSG/ADPCM出力とミキシング段

CH32V303系（V303/305/307）は12bit DAC×2chを内蔵する（V203系列には非搭載）。PSG（L/R）とADPCMはCH32V303内部でデジタル加算してから、DAC 2ch（L/R）としてアナログ出力する。

```
CH32V303内部：
  PSG(L) + ADPCM(パン処理後L分) → デジタル加算 → DAC_OUT_L
  PSG(R) + ADPCM(パン処理後R分) → デジタル加算 → DAC_OUT_R
```

L/Rそれぞれで「FM（YMF825→MCP6001差動SE変換）」と「PSG+ADPCM（CH32V303 DAC）」を抵抗ミキシングし、ヘッドフォンはステレオ、スピーカーはL+Rミックスでモノラル出力（PAM8302A×1を維持）とする。

```
YMF825(L) → R1/R2 → MCP6001(L) 差動→SE変換 → AUDIO_MONO_L ─┐
CH32V303 DAC_OUT_L → （アクティブLPF：CH32V303内蔵OPA活用）→ PSG_ADPCM_L ─┴→ 抵抗ミックス → CH_L_MIX

YMF825(R) → R1'/R2' → MCP6001(R) 差動→SE変換 → AUDIO_MONO_R ─┐
CH32V303 DAC_OUT_R → （アクティブLPF）→ PSG_ADPCM_R ─┴→ 抵抗ミックス → CH_R_MIX

CH_L_MIX ──R10──→ J1 Tip(L)   ┐
CH_R_MIX ──R11──→ J1 Ring(R)  ┴→ ステレオヘッドフォン出力

CH_L_MIX ──R_L(新規)──┐
CH_R_MIX ──R_R(新規)──┴→ SPK_MONO_MIX → C2 → PAM8302A(1個・現行品流用) → SPK(モノラル)
```

MCP6001は2個必要（L/R各1個）。新規部品はR_L・R_R（ミックス抵抗、定数は実機調整）のみ。PAM8302A・J1のNCスイッチ自動ミュート回路は現行のまま流用する。CH32V303の内蔵デュアルOPAをDAC後段のアクティブLPFとして活用する（パッシブRCより低インピーダンス駆動が可能）。

旧spec記載のAUDIO_IN（外部音声入力）・JP1バイパス回路一式は廃止する（理由は§8参照）。

## 6. 外部接続・インターフェース

### 6.1 エッジパッド一覧

旧B基板との最大の違いは、SPI生信号がCH32V303の登場により**B基板内部に完全に閉じ込められる**点である。さらにCH32V303のSWD（PA13=SWDIO・PA14=SWCLK）がUART3（PA13=UART3_TX2・PA14=UART3_RX2）と同一ピンに多重化されているため、COMM_TX/RXとSWDを兼用でき、専用SWDエッジパッドが不要となった。

**旧B基板のエッジパッド（計13本）：** デジタル側8本（VCC_3.3V・GND・SPI_SCK・SPI_MOSI・SPI_MISO・CS_YMF・RST_YMF・IRQ_N）＋アナログ側5本（AMP_5.0V・GND・SPK+・SPK−・AUDIO_IN）

## 8. 設計根拠メモ

### CH32V203ではなくCH32V303を採用した理由

CH32V203は内蔵DACを持たずPWM+フィルタの擬似DAC方式が必要になる。CH32V303系はDAC×2chを内蔵し、PSG/ADPCM出力の回路をシンプルにできる。加えてFPU内蔵によりDSPフィルタ係数計算が容易、SPI×3・I2S対応など拡張性も高い。

### YMF825 2枚同期を「CS共有」ではなく「CS分離」とした理由

旧spec §7.1の「SCK/CS/RST共有・MOSI分岐」方式は、両チップに同一コマンドが同時着弾するため独立した左右発音制御ができない。CS分離（GPIO+1本のコスト）により真のステレオパン・音色制御を実現する。

### YMF825(R)用クリスタルを独立2個実装とした理由

YMF825のXI/XOはピアス発振回路（チップ内蔵インバータが水晶を挟んで自励発振する回路）の能動素子である。2チップを同一水晶へ並列接続すると、2つの発振回路が同じ水晶を同時駆動する形になり、発振不安定化・個体差による周波数の引っ張り合い・デューティ比の崩れが起きるリスクがある。マスター/スレーブ方式（1個の水晶を一方が自励発振し他方へクロック注入）も理論上は可能だが、YMF825-EZの外部クロック注入対応有無が未確認であり、確実性と音質を優先して独立2個実装を採用した。基板面積を厳しく詰める必要が生じた場合の代替案として記録のみ残す。

### CH32V303クロックを外付け水晶とした理由

内蔵HSIの精度（推定±1〜3%）はYMF825（12.288MHz水晶ロック）との同時発音時に聴感上明確な音程ズレ（±1%で約17セント、±3%で約50セント級）を生む。プロジェクトはYMF825に特殊な12.288MHz水晶をわざわざ採用して音質を作り込んだ経緯があり、CH32V303側だけ精度を妥協するのは一貫性に欠けるため、外付け水晶を採用した。一般的な8MHz水晶はJLCPCB在庫が見込め、YMF825用12.288MHzのような特殊調達は不要。

### ADPCMストレージをFRAM案からW25Q128JVに最終確定した理由

当初NORフラッシュの書き込み/消去ペナルティ（セクタ消去4KB単位・典型45ms/最大400ms＋ページプログラム256B単位・典型0.4ms/最大3ms、実効80KB/s〜9KB/s）を懸念し、消去不要で高速書き込み可能なFRAM（MB85RS4MT）への変更を一時検討した。しかし実際の用途規模（掛け声等2〜3秒クリップを入れられるだけ・BGM不要）を精査した結果、1ゲーム分のデータ量（仮に1MB程度）でもNORフラッシュの典型速度（約80KB/s・約12.5秒）で十分実用範囲内であり、容量面（16MB・約419クリップ収録可、FRAM512KBなら約52クリップ止まり）でW25Q128JVの方が圧倒的有利と判断し、最終的に確定した。

### CH32V303のSWDをUARTと兼用できる根拠

CH32V303データシートにより、PA13=SWDIO/UART3_TX2・PA14=SWCLK/UART3_RX2であることを確認した。リセット直後はSWDがデフォルト有効となり、ファームウェア起動後にソフトウェアでSWDを無効化してUART3に切り替える運用が可能。WCH-LinkEを接続してNRSTを引いた「Connect under reset」でいつでも再書き込みできる。これによりエッジパッドに専用SWDパッドを設ける必要がなくなった（A基板PA1の時系列多重と同思想）。

### UIAPduinoのPD5/PD6をCH32V303との常時UARTに使える根拠

cartridge_masterのPhase2以降割り当てではPD5=RST_DISP・PD6=IRQ_N(兼LOCAL_UPDI_A)とされていたが、新B基板では以下の理由で実質解放される。PD5(RST_DISP)は起動時一回限りのパルス出力のため、常時UARTとして使用しても競合しない。PD6は旧B基板でYMF825のIRQ_NとしてUIAPduinoに接続されていたが、新B基板ではYMF825がCH32V303配下に移るためIRQ_NはUIAPduinoには来ない。結果、PD5(TX)→CH32V303 PA14・PD6(RX)←CH32V303 PA13のクロス接続でUIAPduino⇔CH32V303間の常時UART通信が成立する。

判断軸は2つ。①ゲームロード時のADPCM一括転送速度（I2C Fast mode+でも実効~125KB/s止まりに対し、UART+DMAなら200KB/s超見込み）、②CH32V303側のCPU負荷（オーディオ生成と並行するためDMA駆動のUART受信でCPU負荷を抑えた方が音声安定性に有利）。なおCH32V303が「UIAPduinoに対するUARTスレーブ的役割」と「YMF825×2・W25Q128JVに対するSPIマスター」を同時に持つことは、別ペリフェラル・別ピンであり不整合は生じない。

### RST_YMF/CH32V303リセットをシステムNRSTと共有とした理由

UIAPduinoのアプリ切り替え機構には`iap_call()`/`iap_return()`（ソフトウェアコンテキストスイッチ・ハードウェアリセットなし）と`iap_run()`（Flash書き換え後に実リセット）の2系統がある。NRSTが実際にアサートされるのは`iap_run()`実行時、すなわちユーザーが別アプリ/ゲームを起動する瞬間のみであり、CH32V303のリセットをこれに連動させることで、アプリ切り替え時に音源が道連れでリセットされ「再起動後も前のアプリの音楽が鳴り続ける」事象を防止できる。一方、メニュー内の軽量なコンテキストスイッチ（iap_call/return）ではNRSTが発生しないため、音声再生が不要に途切れることもない。

### AUDIO_IN廃止の理由

CAR-01規格の14ピン拡張コネクタ（`connector.md`参照）には、そもそもアナログ音声用ピンが存在しない（下列：BAT_IN/GND/5V_OUT/SDA/SCL/UART_TX/UART_RX、上列：CART_READY/GPIO2/GPIO3/GPIO4/SPI_SCK/MOSI/MISOの計14本のみ）。したがって「拡張アダプタ経由でmp3プレイヤー等の外部音声をミックスする」という用途は、旧B基板のAUDIO_INをもってしても元々実現不可能だった。AUDIO_INは元々カートリッジ内にMP3再生ユニットを内蔵する検討の名残だったが、新B基板はYMF825×2・CH32V303・W25Q128JV等でスペースを使い切るため、その内蔵余地自体が消滅している。CH32V303が自前のフラッシュからADPCMを再生できることで、AUDIO_INが想定していた用途の大部分は代替可能なため廃止した。これに伴いUIAPduino側のPC3（旧PWM_AUDIO）ピンも解放可能になる（別文書側対応、PENDING #4）。

### 裏面GNDベタ方針をゾーン限定方式に緩和した理由

旧spec §3.3の「裏面全面GNDベタ・配線禁止」は、当時のB基板（YMF825単発・19×27.8mm、面積に余裕があった）だからこそ採用できた、やや過剰に厳格な方針だったと判断した。音質面で本当に重要な「アナログ出力直下のGND経路の健全性」をSPOUT1/2まわりに限定して死守しつつ、それ以外（ノイズ感受性の低いデジタル信号・電源系）は裏面配線を許可することで、§3.4で懸念した面積不足のリスクを大幅に緩和できる。
